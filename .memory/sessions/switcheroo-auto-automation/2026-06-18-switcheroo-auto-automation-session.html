Open risks

  • CapsLock+Tab was wired and persisted, but not manually exercised on the user's machine because testing focused on the --auto path.
  • --auto disables global hotkeys, so automation cannot exercise actual hotkey invocation; it only drives the overlay API.
  • The named-pipe server accepts any local process; fine for local testing but should be documented.
  • Config migration is one-way. Keeping old and new config in sync is not implemented.
  • RunOnStartup shortcut creation silently fails under --auto/non-elevated scenarios.

Glossary

Terms
  • --auto: CLI flag that suppresses blocking startup dialogs so automated tests can run.
  • Named pipe: Windows inter-process communication channel used by the automation server.
  • Dispatcher.Invoke: WPF mechanism to run code on the UI thread; fixed thread-affinity errors in automation.
  • IsAltTabWindow: Filter that decides which top-level windows appear in the Alt+Tab list.

## Hypothesis → verification

- H1: Build fails because `WinApi` is internal. Verified by reading error output; fixed by making class public.
- H2: GUI crashes on save because AutoStart shortcut creation throws. Verified by reproducing crash; fixed with try/catch.
- H3: Main hotkey reverts because `ReloadConfig` does not re-apply hotkey after Options closes. Verified by observing Alt+Space returns after options; fixed by calling hotkey reload in `ReloadConfig`.
- H4: Previous-app shortcut does not switch windows because it was calling `SwitchToThisWindow` on windows not passing `IsAltTabWindow`. Verified by code inspection; fixed to use `AppWindow.IsAltTabWindow()` and `SwitchTo()`.
- H5: Blocking "hotkey already in use" popup prevents automation. Verified on every startup; fixed with `--auto` flag that skips hotkey registration and update-check popups.
- H6: Automation pipe responses show `?` due to UTF-8 BOM/encoding mismatch. Verified by running test script; fixed by using `new UTF8Encoding(false)` on both sides and reading line-by-line.

## Decisions

- Config path moved from `%USERPROFILE%\switcheroo\config.jsonc` to `~/.config/.switcheroo_plus/config.jsonc`. Legacy file is migrated automatically if present.
- `--auto` mode suppresses startup dialogs but still starts the named-pipe server so tests can connect.
- Automation uses a dedicated thread + `NamedPipeServerStream` (Byte mode) rather than async/Task, because WPF Dispatcher/thread-affinity issues surfaced when commands were executed on a captured `SynchronizationContext`. Final fix was to dispatch each command via `MainWindow.Dispatcher.Invoke`.
- JSON serialization kept dependency-free via a small internal `JsonHelper`.
- Previous-app logic now filters with `AppWindow.IsAltTabWindow()` and calls `SwitchTo()` instead of `SwitchToThisWindow`.
- The root `AGENTS.md` was updated with a safety rule: never start `switcheroo_plus.exe` or any interactive Windows process without a defined timeout and a reliable communication/termination mechanism.

## Open risks

- CapsLock+Tab was wired and persisted, but it has not been manually exercised on the user's machine because testing focused on the automation path under `--auto`. If the hook still swallows CapsLock unexpectedly, revisit `PreviousAppHook` and the `CapsLock` flag detection in `OptionsWindow`.
- `--auto` disables global hotkeys, so automation tests cannot exercise actual hotkey invocation; they only drive the overlay API. A future harness could send synthetic input if needed.
- The named-pipe server runs on a background thread but does not enforce authentication/ACL; only local clients can connect, but any local process can send commands. This is acceptable for local auto-testing but should be documented.
- Config migration is one-way (old file is read once, then new file is written). If the user wants to keep both in sync, that is not implemented.
- `RunOnStartup` shortcut creation still silently fails under `--auto`/non-elevated scenarios; the user is not notified because it is wrapped in try/catch. This matches the request to prevent crashes, but may hide legitimate configuration issues.
